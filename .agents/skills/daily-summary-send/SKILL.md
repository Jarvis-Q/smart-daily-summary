# 每日工作摘要生成器 · 发送（Codex 版）

> 本 skill **只发送，绝不采集或生成**。生成是独立的 `daily-summary:generate`（见该 skill）。
> 严格分离：本 skill 内禁止调用 `gather_data.py`，也不要顺手改写日报内容
> （除非发送被服务端拒绝且需修正，见下）。

## 插件根目录怎么取

本 SKILL.md 位于 `<插件根>/.agents/skills/daily-summary-send/`。经软链安装时
（如 `~/.agents/skills/daily-summary-send` → 仓库内目录），请先用 `readlink` 解析
真实路径，**取其上三级即插件根**。据此拼出脚本绝对路径再执行——不要写死任何绝对路径。

## 用法

**不带参数** —— 发送最新日报：

```bash
python3 <插件根>/scripts/send_report.py
```

脚本会自动定位 `config.json` 中 `local_output_dir` 下最新的 `daily-summary-YYYY-MM-DD.md`。
注意"最新"是按**文件名字典序**取（`sorted(candidates)[-1]`），不是按修改时间——
刚补写的历史日报**不会**被选中，要发它必须显式传路径。

**带参数** —— 发送指定文件：

```bash
python3 <插件根>/scripts/send_report.py <文件路径>
```

脚本内部会校验文件是否存在，不存在则报错退出。`workDate` 由文件名解析，不是当天日期。

## 发送前自检（强烈建议，能省掉一轮失败请求）

服务端对**每个任务**的 `预估总耗时` 有硬性区间要求，越界会整单打回。发送前先本地核对：

- 每个任务的 `预估总耗时` 必须在 **0.5 ~ 4 小时**之间（含两端）
  - 小于 0.5 → `工作耗时最少0.5小时`
  - 大于 4 → `工作耗时不能大于4小时`
- **工作详情（workDetail）长度不能超过 2000 个字符**：超长时脚本本地截断到 2000 字符
  并打印 ⚠️ 警告后照常发送；看到该警告说明日报写得太长，下次生成时应精炼
- `AI 辅助耗时`、`Token 消耗量` 与 `AI 请求数` 可以为 0，不受此限
- 违规时**不要为了过校验而虚报工时**：零碎工作向上合并、大块工作按真实子结构向下拆分，
  拆分后各任务的 AI 耗时/Token 之和必须仍等于原合计（只重新分配，不增减）

新增字段的兜底行为（不会导致发送失败，但会影响归属准确性）：

- 日报缺 `AI 请求数` 行 → `requestCount` 按 0 上报（正则只认非负整数，天然不会为负）
- 日报缺 `工作分类` 行，或值不在 `data/categories.json` 中 → 回退 `dev` 并打印警告
- 日报缺 `所属项目` 行，或项目名不在本地缓存中 → 回退默认项目并打印警告
- 看到 `⚠️` 开头的回退警告时，说明该任务的归属**不准确**。若在意归属，
  先修正日报中的字段值再重发，不要放任它落到默认项目上。
- 项目列表有变动（新项目建好但搜不到）时，执行
  `python3 <插件根>/scripts/projects.py refresh` 刷新本地缓存。

> **发送阶段不会自动拉取项目列表**：本 skill 读取项目缓存时只用本地缓存文件，
> 缓存不存在或为空并**不会**触发联网 refresh，而是让所有任务直接回退到默认项目并逐条
> 打印警告。因此首次使用本插件前，务必先手动执行一次
> `python3 <插件根>/scripts/projects.py refresh` 建立缓存。

> **发送成功后会自动累计各项目的使用频次**（写入本地 `project-usage.json`），
> 这是生成阶段 `projects.py frequent` 高频清单的数据来源，纯本地统计、不额外联网。

## 执行与结果反馈

运行后向用户反馈发送结果（成功/失败/解析错误）。

**过滤输出时务必保留错误信息**。脚本会打印完整 Payload，输出很长，但失败原因藏在服务端
返回的 JSON 里（`"code"` / `"msg"` 行，以引号开头）。用排除式过滤（如 `grep -v '^\s*"'`）
会把报错一起滤掉。请用白名单式过滤：

```bash
python3 <插件根>/scripts/send_report.py 2>&1 | grep -E '"code"|"msg"|来源|解析到|发送成功|发送失败'
```

## 注意事项

- **非交互即自动确认**：脚本用 `sys.stdin.isatty()` 判断，通过工具调用运行时 stdin 不是
  终端，会**直接发送**、不再二次确认。因此调用前就要确信内容无误——这是一次出网的、
  不易撤回的动作。
- **失败会自动重试 3 次**（间隔 3 秒）。服务端拒绝时不会产生记录，但重跑一次就是 3 次
  请求，所以定位问题优先靠本地复算，不要靠反复发送试探。
- **重复提交同一 `workDate` 的行为未知**（覆盖还是新增记录不明确）。已成功发送的日报若需
  更新，先与用户确认，不要擅自重发。

## 安全护栏

日报正文会出网。本项目为医疗语境，**严禁**发送含患者姓名/病历号/手机号/身份证号等个人
标识的内容，以及任何密钥、令牌、密码。脚本在出网前会对疑似凭证做保守脱敏兜底（命中时会
打印脱敏处数），但那是兜底，不是许可——内容本身就不该包含敏感原文。
